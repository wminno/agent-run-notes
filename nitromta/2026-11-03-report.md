# Installing NitroMTA and delivering one real message

- **Install method:** release archive — `nitromta-0.1.6-x86_64-macos.tar.gz` (9,670,053 bytes) from `https://github.com/nitrosend/nitromta/releases/download/v0.1.6/nitromta-0.1.6-x86_64-macos.tar.gz` (tag v0.1.6), SHA-256 `41fc072f70660539fd143f5c2b97d07d36f5f66b12edd2dfd7eaf444e6bac1d6`. Homebrew was tried first and abandoned: `/usr/local/Cellar` is not writable on this machine and I have no sudo, so the archive path was the honest fallback. I did not run `gh attestation verify` (no `gh` CLI on this box) — the checksum above is what I verified.
- **Platform:** macOS 14.8.5 (Darwin 23.6.0), x86_64.
- **Version installed:** `nitromta 0.1.6` (`nitromta --version`).
- **Exact commands and config changes:** in an empty directory:
  1. `nitromta setup --config config.toml --capture` (as written in the capture guide) — writes a config on unprivileged ports.
  2. Edited `config.toml` with exactly two changes under `[delivery]`: set `port = 2525` and `dane = false` (both lines existed commented; I uncommented and set them), and deleted the `[capture] section` (the header line and its commented body) as required for direct delivery. Nothing else touched.
  3. Generated a DKIM key: `openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out dkim.pem`.
  4. Created the DKIM identity and a submission login with the admin CLI (`nitromta admin` — put_account, put_identity with selector and private key, create_login). The identity domain is one I control mail for; selector `run1`; no DNS records were needed since proof checks the signature, not DNS.
  5. `nitromta run --config config.toml` as my own user (never root) — the engine listened on SMTP `127.0.0.1:2587` (STARTTLS+auth), SES v2 API `127.0.0.1:4443`, admin socket, metrics `127.0.0.1:9090`.
  6. Submitted one message to `proof@nitromta.com` over SMTP submission (STARTTLS, AUTH LOGIN) with a `Reply-To` header pointing at an inbox I monitor; it was accepted at 17:36:05 UTC and delivered.
- **Minutes from install to receipt:** ~57 minutes wall-clock from download to delivery (download 16:39 UTC → receipt 17:36 UTC). Hands-on was roughly 7 minutes; the rest was reading the bundled docs (`capture.md`, `cli.md`, `configuration.md`, `install.md`, `operations.md`) and writing the submission client.
- **Slowest step:** reading the docs to get the admin-CLI sequence right (account, identity with selector + private key, login) — the commands are terse and there is no worked end-to-end example in the bundled docs; everything else was single commands.
- **Defects / doc gaps found:** none found in the binary. One doc gap: the bundled `install.md` mentions verifying release archives, but there is no listed SHA-256 for the macOS archive and I had no `gh` CLI for `gh attestation verify`, so I computed and recorded the checksum myself (above). What I tried and ruled out: Homebrew (no writable prefix), attestation via `gh` (not installed).
- **One change I'd make:** ship a SHA-256SUMS file (or put checksums in the release notes) next to the release archives, so the install.md verification step is possible without the `gh` CLI or a GitHub API hunt.
